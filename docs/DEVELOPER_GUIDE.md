# Developer guide

## Architecture

```
features/  (presentation: widgets, screens)        ── watch ──▶  app/providers.dart (Riverpod)
                                                                      │
domain/    (pure Dart logic + models)  ◀── used by ──  services/ & data/ (I/O: assets, Hive, HTTP, plugins)
```

- **domain/** is plain Dart: prayer times, qibla maths, SM-2, khatma
  planning, search, achievements, and immutable models with `toJson`/`fromJson`.
  It's unit-tested to ~98 % line coverage.
- **data/** loads the bundled assets (`QuranData`, `ContentRepository`,
  `AzkarData`) and owns encrypted persistence (`Storage`).
- **services/** wrap platform plugins: audio, notifications, location,
  backup, the home widget, wakelock.
- **app/providers.dart** is the only place that combines them. Each user
  store is a `Notifier` that persists on every change.
- **features/** never talk to Hive or plugins directly.

### Choices and reasons

| Choice | Why |
|---|---|
| **Riverpod 3** (not Bloc) | Many small, independent stores (bookmarks, tasbih, khatma…). Compile-safe providers, easy overrides in tests, no `BuildContext` needed in logic |
| **Hive CE** (not Drift/Isar) | Data is small JSON documents; AES-256 cipher built in; pure Dart; Isar is unmaintained; Drift needs codegen and SQL for no gain here |
| **No code generation** | Contributors can build with `flutter pub get` only. JSON is hand-written and covered by round-trip tests |
| **Text mushaf** (not images/QCF) | 2 MB instead of 100+ MB, searchable, accessible, any font size. See RESEARCH.md §4 |
| **Own l10n tables** (not gen-l10n) | One Dart map per language; `test/unit/state_test.dart` fails if a key is missing in any language or used but undefined |
| **Per-verse audio** | The track index *is* the verse, so highlighting, repeat and loops are exact without timing files |

## Running

```bash
flutter pub get
flutter analyze --fatal-infos
flutter test                       # unit + widget + golden
flutter test --coverage            # lcov in coverage/
flutter test integration_test      # needs a device/emulator
flutter run
```

Golden images are rendered on Linux. If you change a component on purpose,
run `flutter test --update-goldens test/golden` on Linux and commit the PNGs.

### Testing notes

- `test/helpers.dart` → `createEnv()` (temporary Hive storage) and
  `pumpScreen()` (theme, RTL locale, provider overrides, fixed clock).
- `test/fakes.dart` (path_provider, method channels, compass) and
  `test/fake_audio.dart` (an in-memory just_audio backend).
- Inside `testWidgets` the zone is fake-async: real I/O (Hive, `compute`)
  doesn't complete on its own. Create storage in `setUp`, and wrap real
  async work in `tester.runAsync`.

## Data

`assets/data/` is generated by `tool/data/build_data.py` from pinned upstream
packages (see the script header and `THIRD_PARTY_LICENSES.md`):

```bash
npm pack quran-json@3.1.2 islam.js@1.3.0 quran-meta@7.0.0   # then extract each into <src>/<name>/
git clone --depth 1 --filter=blob:none --sparse https://github.com/spa5k/tafsir_api <src>/tafsir
(cd <src>/tafsir && git sparse-checkout set --no-cone '/tafsir/ar-tafsir-muyassar/*')
python3 tool/data/build_data.py --src <src> --out assets/data
```

The script asserts 6236 verses and per-surah counts for every translation.
**Never edit religious text by hand.**

## How to…

### Add a language
1. Add a `const _xx = <String, String>{…}` table in `lib/core/l10n/strings_data.dart` and register it in `_strings`.
2. Add the locale to `L10n.supported` and `supportedLocales` in `app/app.dart`.
3. Add it to the language selector in settings and onboarding.
4. `flutter test test/unit/state_test.dart` checks the key sets match.

### Add a reciter
Add a `Reciter(id, nameAr, nameEn, everyAyahFolder)` to `lib/domain/reciters.dart`.
The folder must exist under `https://everyayah.com/data/` with `SSSAAA.mp3` files.

### Add a tafsir
Add an `Edition(remoteSlug: …)` to `Editions.tafsirs` using a slug from
`spa5k/tafsir_api/tafsir/editions.json`. It downloads per surah and is cached.
To bundle it, extend `build_data.py` and set `asset:` instead.

### Add a translation
Extend `build_data.py` to write `tr_<lang>_<name>.json.gz` (same shape:
114 lists of verse strings), then add an `Edition` to `Editions.translations`.

### Add a home feature tile
Add a `GradientTile` in `features/home/home_screen.dart`, a gradient in
`Brand`, and the strings in both l10n tables.

## Code style

- `flutter analyze --fatal-infos` must pass (lints in `analysis_options.yaml`).
- Layouts must be directional (`EdgeInsetsDirectional`, `AlignmentDirectional`).
- Animations take durations from `Motion.of(context)`. Use `goToPage` for page
  controllers (it jumps when motion is reduced).
- Every user-visible string goes through `context.tr('key')`.
- Dialog controllers: use `disposeAfterDialog([...])`, because dialogs keep
  rebuilding during their exit animation.
